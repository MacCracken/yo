# P(-1) review — 2026-11-08 (0.7.2)

**Scope.** All of yo as it ships after the toolchain bumps of 0.6.2 – 0.7.1
(cyrius 6.6.2 → 6.7.18):
- `src/`: twelve files, about 2,650 lines, both backends;
- the unit suite, the fuzz and bench harnesses, and the QEMU smoke script;
- both CI workflows;
- the docs.

This is yo's first filed audit. The question it answers is what is wrong,
missing or untested in what yo already ships. New features are out of scope:
where a finding needs one, it is deferred to the roadmap.

**Method.** The P(-1) steps, in order:
0. **Intent.** Read the roadmap, CHANGELOG, state.md, both ADRs and architecture
   note 001. Checked GitHub issues (none open).
1. **Cleanliness.** `cyrius audit`: fmt clean, 8 lint warnings (long lines), 46
   undocumented public functions, tests green. CI gated none of the first three.
2. **Benchmark baseline.** `cyrius bench`, three runs before any repair.
3. **Internal deep review.** Every line of `src/`, the tests, CI and the smoke
   script. Two independent reviews ran in parallel without seeing these findings,
   so they could not anchor on them: one on untrusted input and memory safety,
   one on behaviour, syscalls and project hygiene. The first independently
   reached B, C, D and G, the second D, F and G. They contributed the end-to-end
   reproduction of A (this review had found the constant ident and the unset
   IPv6 mode by reading, but not that a dead host reads as alive), S, J, P, Q,
   the stale-state half of M, and the 2 GiB crash in H. The memory-safety review confirmed B with a guard word
   allocated after the query buffer, which the overflow overwrote.
4. **External research.**
   - RFC 1035 §3.1 (255-octet names), RFC 5452 §9.1–9.2 (question match,
     unpredictable ID), RFC 4343 (case), RFC 4007 §11.2 (numeric zones),
     RFC 952 / 1123 (hostname characters);
   - glibc's `res_hnok`, which keeps a non-hostname PTR answer away from
     iputils ping, and iputils' limits (`-s` 65507, the minimum interval for
     non-root users);
   - Linux: `raw(7)`; the order in `ip_protocol_deliver_rcu`, where
     `raw_local_deliver` runs before `icmp_rcv` checks the checksum;
     `SO_RCVTIMEO` {0, 0} meaning "never time out"; `signalfd`, `ppoll`, and
     why a blocked SIGINT is queued even when its disposition is SIG_IGN;
   - taar's 0.6.2 audit, whose findings A, C, D, F and G recur here as I, K and N;
   - the cyrius 6.7.18 guide's rule that a bare `var a[N]` is N bytes in a
     function but N × 8 at module scope;
   - the agnos `udp_recv#53` source-address record layout, as taar confirmed
     it in the kernel source.
5. **Repairs.** A guard added to an existing function got its test first, and
   the test failed against the unrepaired code: 15 assertions in the DNS batch
   went red, including the forged datagram that was read. **Every new guard was
   mutation-checked**, 37 in all: remove it, see a suite go red. All 37 were
   killed. Behaviour the unit suite cannot reach is pinned by a new integration
   harness, `tests/integration/run.sh`. Its checks run the binary in a network
   and mount namespace: 28 pass on 0.7.2, and 18 of them fail on the 0.7.1
   binary.
6. **Post-repair benchmarks**, the full gate set run from the workflow YAML on a
   fresh checkout, and the AGNOS QEMU smoke.
7. **Documentation audit.**

**Result.** 25 findings: 1 high, 9 medium, 11 low, 4 info. All are fixed in
0.7.2. The items that need a behaviour decision or feature work are deferred to
the roadmap with their reasons; see *Deferred*.

## Findings

**A — RAW reply cross-talk.** On the SOCK_RAW fallback the kernel does not
demultiplex: every echo reply on the host reaches every raw socket, and yo
filters them itself. It compared seq and ident, but the ident was the constant
`0x1234`, the same in every yo process. And `platform_icmp6_open` never set the
mode flag that gates the ident check, so on IPv6 RAW the ident was not compared
at all. Two yo processes on raw sockets therefore accepted each other's replies.
This is the fallback root gets in a container or a fresh network namespace,
where `ping_group_range` excludes everyone; concurrent health checks are exactly
the case.
*Reproduction* (`unshare -r -n`, a dummy interface for the black hole, both
probes started together with `-c 3 -W 500 -i 500`): the 0.7.1 binary reported
the dead host as `3 sent · 2 received · 33% loss`, **exit 0**, in 6 of 6 runs
over IPv4 and IPv6.
*Fix:* a random ident per process (`platform_random_u16`), and the IPv6 open
records its mode. The acceptance rules moved into the pure
`probe_reply_is_ours`.
*Not done:* checking the reply's source address. iputils does not, and it would
break replies from another address (pinging 0.0.0.0, multicast). Deferred as a
decision.
*Tests:* `audit A+G+S`; integration "A: v4 / v6 dead host stays dead beside a
live probe".

**B — hostname heap overflow.** `_dns_encode_qname` capped each label at 63 bytes
but never capped the whole name at 255, and it wrote into a 512-byte `alloc`.
A hostname comes from argv, which can be about 128 KiB, so a name like
`a.a.a.…` wrote that far past the buffer. In a normal run nothing live sat
there, so nothing crashed; the bytes were attacker-chosen all the same. It
matters most when yo is installed with `cap_net_raw`, as ping often is.
*Fix:* the cap is checked before each byte is stored, so nothing is ever
written at or past byte 255.
*Tests:* `audit B` uses canaries past the 255-byte limit of a 300-byte buffer
and past the query buffer. Fuzz invariants 10 and 11 fail under
`cyrius fuzz --poison` when the guard is removed.

**C — PTR injection.** A DNS label is binary on the wire. `_dns_decode_name`
copied PTR label bytes as they were, and the banner printed them. So whoever
controls an address's reverse zone, or can spoof the reply, could write ESC
sequences to the user's terminal, or a CR / LF that forges whole `seq=` or
summary lines. Anything reading the output, scripts included, would be misled.
glibc's `res_hnok` drops such names before iputils prints them.
*Fix:* `_dns_name_is_hostname` accepts letters, digits, `-`, `_` and `.` only,
and `_dns_parse_ptr_response` rejects any other name. The banner then shows
none.
*Tests:* `audit C`; fuzz invariants 21 and 22; integration "C" (the fake
server's ESC-laden PTR never reaches the output).

**D — AGNOS request-buffer overrun.** `var _ag_req[256]` is a module-scope bare
array, so it is 2048 bytes. `platform_icmp_send_to` copied `pkt_len` bytes into
it with no bound. Globals are laid out in declaration order, so `-s 2041`
overwrote `_ag_req_len`, `-s 2056` `_ag_req_addr` (the ping went to the
payload's bytes), and larger values the DNS globals after them.
*Fix:* a request over 2048 bytes is refused with -EMSGSIZE, and the CLI caps
`-s` at 65507 (H).
*Tests:* the host suite cannot reach the AGNOS arm. The QEMU smoke now types
`yo -c 1 -n -s 3000 10.0.2.2` and asserts `send failed: -90 EMSGSIZE`; it passes.

**E — waits nobody could interrupt.** Three related defects:
- **`-W 0` hung forever.** It became `SO_RCVTIMEO` {0, 0}, which means "never
  time out". SIGINT is blocked so that a signalfd can watch it, so Ctrl-C could
  not end the blocking `recvmsg` either. Measured on 0.7.1: still running 4 s
  after SIGINT, and SIGKILL was needed.
- **Ctrl-C was seen only between probes.** A reply wait could not be cut short,
  and neither could an interval sleep. Measured: 8.5 s after SIGINT with
  `-i 10000`, and 4.4 s with `-W 5000`.
- **Ctrl-C did not stop a multi-target run.** It ended the current target, then
  stayed blocked through the next target's DNS, and that target printed a bogus
  `0 sent` summary.

*Fix:*
- `-W` must be at least 1 ms.
- The probe loop waits with `platform_wait_readable`, a `ppoll` on the socket
  and the signalfd against an absolute `-W` deadline. That also ends the old
  worst case of about 2×`-W` on a busy raw socket.
- It sleeps with `platform_sleep_interruptible`.
- Ctrl-C ends the run after the current target's summary.
- The watch is removed after each probe loop, so in a later target's DNS Ctrl-C
  works at once. If `signalfd` fails, SIGINT is unblocked again (it used to stay
  blocked for the rest of the run).

*Tests:* `audit E+H` (`-W` limits); `audit E: interruptible waits` sends SIGINT
to itself and checks a 5 s wait ends within a second; `audit E+M`. Integration
measures 1 ms from SIGINT to exit for both waits, and checks a two-target run
stops after the first target.

**F — per-probe memory growth.** cyrius's `alloc` is a bump allocator with no
free. On every call, send, recv, the clock read, the interrupt check and the
sleep each allocated their scratch: sockaddrs, the msghdr, the iovec, the cmsg
buffer, the timespec and the siginfo. Measured peak RSS:

| probes | 0.7.1 | 0.7.2 |
| ---: | ---: | ---: |
| 30,000 | 16.6 MB | 13.5 MB |
| 60,000 | 28.9 MB | — |
| 70,000 | — | 13.3 MB |

That is about 35 MB a day at one probe per second. With `-i 0` on loopback, RSS
grew from 22.7 to 41.2 MB in 2 s, until `alloc` would fail.
*Fix:* static module-scope scratch buffers.
*Tests:* `audit F` runs 200 probe iterations and checks they allocate 0 bytes
(`alloc_used`); integration "F" checks RSS stays flat over 2 s of flood probing.

**G — the 16-bit sequence wrap.** `icmp_build_echo_request` writes `seq & 0xFFFF`,
but `probe.cyr` compared the reply with the full i64 counter. Every reply from
probe 65536 on was rejected, and each waited out `-W`. 0.7.1 at `-c 65538`
printed `65538 sent · 65536 received · 0% loss`; the `0%` is truncation, see
*Deferred*. *Fix:* compare the low 16 bits. *Tests:* `audit A+G+S` (65543
matches wire 7); integration "G".

**H — unbounded numeric flags.** Each flag was checked only for `< 0`:
- `-s 65508` and up sent nothing: `sendto` returned EMSGSIZE, and yo printed
  `timeout` for every probe.
- `-s` past 2 GiB made `alloc` return 0, and yo wrote through the null pointer:
  SIGSEGV, exit 139.
- `-W` near i64 overflowed `timeout_ms * 1000`.

*Fix:* `-s` ≤ 65507 (iputils' limit), and `-W` and `-i` ≤ 2147483647 ms.
`CLI_ERR_RANGE` names the flag. The probe also checks its allocations.
*Tests:* `audit E+H`; integration "H".

**I — silent public-resolver fallback.** This is taar's 0.6.2 finding A, also
present in yo's own resolver. `_dns_resolv_conf_nameserver` returned the same
code for "no nameserver line" and for "nameserver lines, none usable", and both
fell back to 1.1.1.1. A host whose resolv.conf lists only IPv6 resolvers
therefore sent every lookup, in cleartext, to a third party, bypassing a VPN's,
a split-horizon or a filtering resolver.
*Fix:* `DNS_RESOLV_UNUSABLE`, and the pure `_dns_resolv_choose` fails closed
for it. A file naming no server, or no file, still falls back.
*Tests:* `audit I+N`; integration "I" uses a trap listener on 1.1.1.1 and checks
it hears nothing in the unusable case and the query in the no-server case.

**J — CI supply chain.** Three problems:
- `actions/checkout@v4` and the third-party `softprops/action-gh-release@v2`
  were mutable tags, and the latter runs with a write token.
- Both workflows piped cyrius `main`'s `install.sh` into `sh`. That script is
  what verifies the release tarball's checksum and Ed25519 signature, so an
  unpinned copy could skip all of it.
- `release.yml` granted `contents: write` workflow-wide, which reached the
  reusable CI gate too.

*Fix:*
- Both actions are SHA-pinned (v4.3.1 `34e1148`, v2.6.2 `3bb1273`; verified with
  `git ls-remote`), and checkout runs with `persist-credentials: false`.
- The installer is fetched at the pinned cyrius tag.
- `contents: read` is the default, with write on the release job alone.

**K — DNS reply authentication.**
- The query ID was `now_us & 0xFFFF`, which is predictable.
- The Linux UDP socket was unconnected, and `recvfrom` discarded the source, so
  any host that guessed the ephemeral port could answer. The failing-first test
  read a forged datagram from a third socket.
- On AGNOS the kernel delivers by port alone.
- The question section and the answer's CLASS were never checked.

*Fix:*
- a `getrandom` ID;
- a connected socket on Linux;
- on AGNOS the peer is recorded and other sources are dropped, using the record
  layout taar verified; the pure `platform_peer_match` is shared;
- `_dns_question_matches` (RFC 5452 §9.1: ID, name case-folded, type, class,
  QDCOUNT 1);
- CLASS IN required.

The four resolve bodies became one `_dns_exchange` (Y).
*Tests:* `audit K` (a loopback forger, the question echo, the peer match);
integration "K" (a forged answer from another port is ignored).

**L — send errors as timeouts.** A failed `sendto` (ENETUNREACH, EMSGSIZE,
EINVAL for a link-local address with no zone) printed `seq=N  timeout`. That
sent the reader looking at the network for what was a local error. *Fix:*
`output_send_error` prints `send failed: -101 ENETUNREACH`. *Tests:* `audit L`;
integration "L".

**M — diag state.** The IPv6 open never recorded its mode (see A), so `--diag`
said "never opened" after a v6 socket had opened and sent. The diag statics
were never reset, so a later target could report an earlier one's socket or
errno. *Fix:* the v6 open sets the mode, and `platform_diag_reset` runs at the
start of each `probe_run`. A side effect of E's poll-based wait is that a
timeout no longer leaves a recv error, which would have silently dropped
`--diag`'s `-11 EAGAIN (timeout …)` line; the wait now records it. *Tests:*
`audit E+M`, the -11 assertion in `audit E`; integration "A/M".

**N — resolv.conf parsing.** taar's 0.6.2 findings D and F, also present in yo.
A token ended only at a space or tab, so `1.2.3.4\r` never parsed. A file over
4 KB could arrive cut mid-line, as `10.0.0.1` for `10.0.0.12`. *Fix:* CR ends a
token. When the read fills the buffer, only complete lines are parsed
(`_dns_resolv_complete_len`), and a cut file with nothing usable fails closed.
*Tests:* `audit I+N`; integration "N".

**O — `%zone`.** The zone went into `/sys/class/net/<zone>/ifindex` unchecked,
so `../../tmp/x` read `/tmp/x/ifindex`. That is argv only, and only a leading
number is read. The digit parse could overflow, and a numeric zone (`%2`,
RFC 4007 §11.2) was looked up as a name.
*Fix:* 1..15 bytes, no `/`, a numeric zone is the index itself, and indexes are
u32.
*Tests:* `audit O`. `../net/lo` would reach `lo`'s real ifindex without the
`/` check, which is what makes the test discriminate.

**P — the wrong-family literal.** `yo -4 ::1` sent `::1` to DNS as a hostname
and failed about 4 s later with "cannot resolve host". *Fix:* the pure
`ipv6_literal_family`; main refuses at once, naming the reason. An IPv4-mapped
literal counts as IPv4, so `-6` refuses it too. *Tests:* `audit P`;
integration "P".

**Q — help and option errors.**
- `lib/flags.cyr`'s `flags_print_help` writes to stderr, so the option rows
  went there while the header went to stdout.
- A bad option printed a bare `yo: bad option`.

*Fix:*
- yo prints the rows itself, in the same format, on stdout. The help strings are
  shared with registration and now state the ranges.
- Errors name the token: `yo: unknown option: --bogus`, or
  `bundled/attached short options are not supported: -c5`.

*Tests:* integration "Q".

**R — AGNOS details.** An open failure on AGNOS printed the Linux
`ping_group_range` hint. `platform_udp_open` ignored `getrandom`'s result, which
on failure left the source port to stack contents.
*Fix:* `platform_icmp_open_hint` is per backend. `platform_random_u16` checks
the result and degrades to the clock.

**S — RAW checksum.** Doc 001 called checksum verification redundant on every
path. On IPv4 SOCK_RAW it is not: `raw_local_deliver` hands the raw socket its
copy before `icmp_rcv` checks the checksum. *Fix:* `probe_reply_is_ours`
verifies it there. *Tests:* `audit A+G+S` (a corrupted reply is rejected).

**T — tests and gates.**
- `tests/yo.fcyr` included no yo source, so the CI step "Bench + fuzz" read as
  coverage that did not exist.
- Reply acceptance had no test.
- The binary never ran in CI.
- `cyrius audit`'s fmt, lint and docs sections were not gated.

*Fix:*
- a real fuzz harness: 20,000 deterministic rounds over every byte parser, with
  22 invariants, run plain and under `--poison`;
- the integration harness, run in CI under `sudo unshare`;
- `cyrius audit` as a CI step.

**U — the QEMU smoke script.**
- An image-build step failing surfaced as "never reached the agnsh prompt".
- QEMU's output went to `/dev/null`.
- `python3 -` puts the current directory on `sys.path`.
- The QMP socket under a deep checkout can exceed the 108-byte Unix socket limit.
- Two concurrent runs wiped each other's work directory.

*Fix:*
- each image step is checked;
- QEMU logs to `qemu.log`, whose tail is printed on a boot failure;
- `python3 -I`;
- the socket goes in a short `mktemp` directory;
- a `flock`;
- the `-s 3000` assertion for D.

**V — cmsg record length.** The walkers read the int at `+16` of a matching
record without checking that the record was at least 20 bytes long, or that it
lay inside `controllen`. The buffer is kernel-filled, so this only ever mattered
for synthetic input. *Fix:* one `_lx_cmsg_find` with both checks. *Tests:*
`audit V`.

**W — stale docs.**
- Doc 001 marked both RAW rows of its five-paths table "correct", and called
  RAW checksum verification redundant.
- CLAUDE.md stated the function-local `var buf[N]` rule as universal.
- The README's `yo -W 2 router.local` means a 2 ms timeout.
- `icmp.cyr`'s header named the `net_send_raw` primitives ADR 0002 rejected.
- `platform.cyr` gave a stale surface count.
- The AGNOS diag comment said the kernel has no ICMP counters (agnos 1.56.48
  added them).
- The diagnosing guide said a second yo on RAW "no longer crosses replies".

All are corrected.

**X — cleanliness.** `cyrius audit` is now fully clean: fmt, lint, docs, tests
and bench. CI runs it, so this cannot accrete silently again.

**Y — refactor.**
- `dns_resolve`, `dns_resolve_aaaa` and both reverse lookups carried the same
  exchange loop; now one `_dns_exchange`.
- The three query header writers are one `_dns_put_header` plus
  `_dns_put_qtail`.
- The two cmsg walkers are one.
- `output.cyr`'s copy of the v4-mapped check is gone.
- The sockaddr writers fill a caller's buffer (`_into`), so the per-probe path
  uses static storage.

## Deferred

Each is in [`roadmap.md`](../development/roadmap.md), with what it waits on.

| Item | Why not now |
| --- | --- |
| reply source-address filtering on RAW | a decision: iputils does not filter, and it would break 0.0.0.0 and multicast replies; the random ident (A) already ends cross-talk |
| loss % truncates (1 lost of 101 prints `0% loss`) | a decision on the summary format |
| `-c 0` sends nothing; there is no continuous mode | a decision |
| no minimum interval for unprivileged users (iputils: 2 ms) | a decision: `-i 0` flooding is bounded by RTT or `-W`, not by policy |
| `-W` / `-i` in ms where iputils uses seconds | a decision; the README example was fixed |
| the interval runs after the reply wait, not send-to-send | a decision |
| any reply on any target exits 0, even if others failed to resolve | a decision |
| integer flags wrap silently past 2^64 (`-s 18446744073709551672` is 56) | in `lib/flags.cyr` (cyrius) or a move to cmdit |
| IPv6 nameservers in resolv.conf | feature work |
| answer owner-name / CNAME-chain validation | feature work (taar defers it too) |
| AGNOS: honour `-W` (`icmp_echo_ex`#100), counters in `--diag`, Ctrl-C (`signalfd`#18) | feature work; the stdlib wrappers are vendored |
| `-v` is parsed and does nothing | a decision: implement or remove |
| ICMP unreachable / time-exceeded replies are not reported | feature work |
| `platform_linux.cyr`'s x86_64 syscall numbers | the aarch64 blocker, already on the roadmap |
| release artifacts carry no checksums or signature | feature work |
| a missing resolv.conf falls back to 1.1.1.1 rather than 127.0.0.1 | a decision (taar holds the same one open) |

Accepted as documented:
- A datagram from the nameserver itself that fails the checks uses up an
  attempt. The connected socket means only the server's address can send one.
- `-s` on AGNOS shapes only the synthesised reply, because `icmp_echo#55` sends
  its own payload (ADR 0002).

**Guards with no discriminating test**, as recorded in source:
- **Fallback paths that cannot be forced:** `platform_random_u16`'s clock
  fallback on both backends (getrandom cannot be made to fail), and the SIGINT
  unblock when `signalfd` fails.
- **A check no real input can distinguish:** the `%zone` 15-byte limit. No
  interface name that long can exist, so a longer one fails either way.
- **Unreachable after another guard:** the probe's out-of-memory check, now that
  `-s` is capped.
- **The AGNOS arm:** the peer filter's wiring, which the QEMU smoke compiles and
  runs but does not attack. The `_ag_req` bound is executed by the smoke.

## Benchmarks

`tests/yo.bcyr`, x86_64. The host's timer floor is about 1.1–1.4 µs per clock
read, measured and subtracted by `lib/bench.cyr`. Medians of three runs:

| Row | Before | After | |
| --- | ---: | ---: | --- |
| `icmp_checksum 64B` | 97 ns | 96 ns | untouched — noise |
| `icmp_build_echo_request 56B` | 208 ns | 206 ns | untouched — noise |
| `ipv4_parse dotted-quad` | 54 ns | 54 ns | untouched |
| `ipv6_parse compressed` | 304 ns | 309 ns | untouched — noise |
| `output_ipv4_to_buf` | 85 ns | 85 ns | untouched |
| `probe_reply_is_ours raw+cksum` | — | 116 ns | new: the RAW acceptance path with S's checksum |
| `dns PTR parse + hostname check` | — | 183 ns | new: C's check on a 10-byte name |
| `dns question echo check` | — | 107 ns | new: K's check |

No optimisation was made, because none is warranted: every row is tens to
hundreds of nanoseconds on a path that then waits milliseconds on the network.
Per invocation (`-c 1 -n 127.0.0.1`, best of 3 × 100) the 0.7.1 and 0.7.2
binaries measure 444–445 and 448–449 µs on this host.

Size: the default x86_64 build is 200,936 B, up from 191,784 at 0.7.1. Under
`CYRIUS_DCE=1` it is 86,248 B, up from 77,096, so about 9 KB of new live code
